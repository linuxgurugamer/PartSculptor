# PG individual vertex collider fallback (0.0.5.13)

Manual KSP 1.12 validation (not run offline):

1. With default `generateVertexCollisionFallback = false`, place a stock tank and cube with supported convex colliders. Add one vertex on a side, move it outward and inward. Verify normal drag, Alt drag, soft selection, group movement, attachment nodes, calculated capacity and undo. Ring edits must still work.
2. Use a B9 model with separate visual and collider transform names selected in the same SUBTYPE, and no strictly compatible collider. Move a vertex: the active compatible collider should be selected, with a `PG collision fallback` tier 1 log. Check the collision hull, volume, nodes, and save/reload. Switch away and back; no deformation must leak into the other subtype's collider.
3. Use a part with an inactive alternate collider, a trigger, a disabled collider, or a degenerate candidate. Verify these are not enabled or selected. Try an edit without a usable match; the screen should report rejection and KSP.log should show `PG collision inventory` including each owned collider's state, path, and candidate rejection details. The edited vertex should return to its old position and undo should not gain a checkpoint.
4. Set `generateVertexCollisionFallback = true` in PluginData/Settings.cfg and restart. Retry on a solid readable visual mesh without a usable collider. Confirm the new private convex MeshCollider (max 252 triangles) follows the visual object's hierarchy, does not enable disabled originals, and volume changes use the paired baseline/edited hull. For an open planar mesh, verify that the hull fails safely. A solid visual mesh with no supported collider at all is eligible only with the setting enabled; unsupported collider types and unreadable native colliders remain rejected.
5. Delete/clear vertex edits and verify the generated collider and private mesh are removed; native colliders and ring edits remain intact. Undo and repeat, then Alt-copy, use symmetry, save/reload and launch with fallback enabled. Verify no duplicate generated colliders or shared-mesh mutations, and that nodes and resources follow. Inspect actual collision in flight: convex hulls may fill holes, overlap existing colliders, or differ from visible concavity. A craft relying on generated colliders must retain the setting.
6. Check both failed and successful fallback logs. Include the part name, transform paths and B9 subtype names in a bug report if the original issue persists.

The Python reference checks validate ranking policy and source integration, not KSP/Unity collider cooking or runtime behavior.
