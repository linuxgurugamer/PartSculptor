# Live attached-face morph tests — 0.0.4.109 (KSP1 editor)

1. Enable **Match attached faces** on any PAW (off by default). Attach two compatible stock tanks end-to-end and change only the touching end of the parent with the Morph tool. As you drag X/Z corner and edge handles, the child's *touching* face should resize along with the parent; child's far end should not change. Repeat with tilt (Alt), radial (Ctrl+Alt), and linked translation (Shift+Alt).
2. With both ends connected in a three-tank stack, morph the **middle part's top end**. Only the neighbor at that top end should get a new face shape. Its far end and the neighbor below the middle part must remain unchanged. Then edit the middle part's bottom end and confirm only the bottom neighbor changes. No cascading to the third part.
3. Reverse direction: select the *child* and morph the face touching its parent. Check that only the parent's connected end is reshaped, not the entire parent or other attached branches. Check that the child/parent joint remains aligned during and after the drag, including with tilt.
4. Undo a single morph drag with Ctrl+Z. Check that **both the driver part and the receiving part** revert together. Cancel a drag with Escape or right-click; verify both touching ends revert. Use **Reset face morph** and confirm identity geometry is attempted on the connected end, even when neither part remains morphed.
5. Disable **Match attached faces** after starting a craft, morph an attached part, and verify its neighbor stays exactly as before. Re-enable and verify a subsequent drag updates the neighbor. **Match node sizes** and **Stretch children** must remain independent toggles.
6. Repeat in 2-way and 4-way symmetry; edit a source with symmetric copies and check that each physical join matches independently, with each neighbor's opposite face intact. Try a source that has a mixed set of supported and unsupported neighbors; one failure must not prevent other matches.
7. Test rotated 90/180/270 degree stack joints, unequal part widths, moderate face tilts, and pre-existing face offsets. Very skewed/oversized shapes, unsupported meshes/colliders, surface attachments, and Career/volume-limited matches should be skipped without exceptions or runaway recursion. Verify nothing changes in flight or simply upon loading a craft.
8. Disable and re-enable the option when working with existing craft; edits should update only the newly edited end faces, not spontaneously modify unrelated saved shapes. Use PartSculptor debug logs to diagnose skipped joints.

The offline checks verify connection routing and fitting math, not actual KSP editor transforms. Test in-game before release.
